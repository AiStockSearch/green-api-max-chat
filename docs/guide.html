GREEN-API Chat — пошаговое руководство

Веб-клиент для переписки в WhatsApp, Telegram и MAX через GREEN-API: несколько инстансов в одном окне, единый список чатов, установка как приложение (PWA). Тестовое задание (frontend) для компании «Грин-Апи».

Безопасность. Во всех примерах — заглушки: 1101000001 для idInstance и YOUR_API_TOKEN для apiTokenInstance. Скриншоты сняты в демо-режиме, реальных ключей на них нет. Никогда не публикуйте настоящие токены в репозитории, issue или на скриншотах.

1Обзор: что умеет приложение

SPA на React + TypeScript (Vite). Список чатов слева, переписка «пузырями» справа. Все запросы идут в HTTP API GREEN-API по схеме {apiUrl}/waInstance{idInstance}/{method}/{apiTokenInstance}.

WhatsAppTelegramMAX
  • Три мессенджера. Для каждого инстанса выбирается WhatsApp, Telegram или MAX. От выбора зависят подсказки, формат chatId, способ авторизации (QR, пароль 2FA, вход по коду в Telegram) и разбор уведомлений.
  • Несколько инстансов одновременно. На экране «Инстансы» видны статусы всех инстансов. В режиме «Все чаты» список общий, у каждого чата иконка мессенджера, сверху фильтр по инстансу. Каждый авторизованный инстанс опрашивается в своём цикле.
  • Чаты. Новый чат создаётся по номеру или chatId. Текст отправляется через sendMessage, входящие приходят через очередь receiveNotification / deleteNotification. Неотправленное сообщение можно повторить.
  • Управление инстансом. «Выйти из инстанса» вызывает GREEN-API Logout. «Убрать из приложения» удаляет инстанс только из браузера. Есть режим партнёра (Partner API): список инстансов, создание и удаление.
  • PWA. Приложение ставится на компьютер, Android и iOS и открывается без сети: оболочка берётся из кеша, запросы к API не кешируются. Когда выходит новая версия, появляется «Обновить».
  • Адаптивная вёрстка и демо-режим без инстанса (?demo=…, см. шаг 9).
Ограничения: поддерживается только текст, медиа не отображаются. Чаты и сообщения хранятся локально в браузере. На один инстанс работает один опрос: если открыть тот же инстанс в нескольких вкладках, очереди могут конфликтовать.

2Получение ключей в консоли GREEN-API

  1. Зарегистрируйтесь или войдите на console.green-api.com. Публичного API регистрации нет, поэтому экран «Регистрация» в приложении ведёт на сайт.
  2. Нажмите «Создать инстанс» и выберите мессенджер: WhatsApp, Telegram или MAX. Для проверки хватит бесплатного тарифа Developer, но у него есть лимиты на число запросов и чатов.
  3. Откройте карточку инстанса и скопируйте три значения:
    ПолеПример (заглушка)Куда вводить
    idInstance1101000001Поле «idInstance»
    apiTokenInstanceYOUR_API_TOKENПоле «apiTokenInstance»
    apiUrlhttps://1101.api.green-api.comПоле «API URL» (по умолчанию https://api.green-api.com)
  4. Чтобы получать сообщения, в настройках инстанса очистите webhookUrl (пока задан свой webhook, очередь HTTP API недоступна) и включите уведомления о входящих.
Токен утёк? Если apiTokenInstance попал в git, чат, лог CI или на скриншот, сразу перевыпустите токен в карточке инстанса. Затем обновите его в cypress.env.json и в секретах GitHub.

Ключ партнёра (partnerToken вида gac.…) выдаёт support@green-api.com. С ним инстансы можно создавать прямо в приложении (шаг 3, «Режим партнёра»).

3Добавление инстанса

При первом запуске открывается экран «Вход». Когда инстансы уже есть, такой же экран «Добавить инстанс» открывается с карточки «Добавить инстанс» на экране «Инстансы». Кнопка «← Инстансы» вверху формы возвращает назад без изменений.

  1. Мессенджер. Выберите одну из трёх карточек: WhatsApp, Telegram или MAX. Выбранная выделена рамкой и галочкой, под карточками одна строка подсказки для этого мессенджера.
  2. Введите idInstance (например, 1101000001) и apiTokenInstance. Токен можно показать или скрыть кнопкой с глазом.
  3. API URL необязателен, но лучше скопировать apiUrl из карточки инстанса. В поле «Название» можно задать подпись на экране «Инстансы», например «Поддержка».
  4. «Запомнить на этом устройстве» сохраняет профиль в localStorage. Без этой галочки он лежит в sessionStorage до закрытия вкладки. Работает менеджер паролей браузера.
  5. Нажмите «Войти» (или «Добавить»). Приложение вызывает getStateInstance. Если ответ authorized, открываются чаты, иначе экран авторизации (шаг 5). Профиль хранится под ключом messenger:idInstance.

Вкладка «Режим партнёра»

  1. Откройте вкладку «Режим партнёра», введите partnerToken и partnerApiUrl и нажмите «Продолжить». Будет вызван getInstances.
  2. В списке «Инстансы партнёра» откройте нужный инстанс. Новый создаётся кнопкой «Создать инстанс» (createInstance), удаляется кнопкой «Удалить» (deleteInstanceAccount). Мессенджер берётся из typeInstance.
  3. Выбранный инстанс проходит авторизацию (шаг 5), затем открываются чаты.
Хранить partnerToken в браузерном SPA допустимо только для демо и тестов. В продакшене Partner API и секреты должны идти через backend.

5Авторизация инстанса: QR и код

Новый инстанс находится в состоянии notAuthorized. Экран авторизации показывает QR (метод qr, обновляется каждые ~5 с), опрашивает getStateInstance и, как только придёт authorized, сам переходит к чатам. Ссылка «Открыть qr.green-api.com» открывает тот же QR в отдельной вкладке. QR можно отсканировать и в карточке инстанса в консоли.

МессенджерГде сканироватьДополнительно
WhatsApp«Настройки → Связанные устройства → Привязка устройства»Ошибка «Instance has auth…» — кнопка «Logout инстанса и новый QR». Пароля 2FA нет.
Telegram«Настройки → Устройства → Подключить устройство»Облачный пароль (sendAuthorizationPassword). Есть вход по коду.
MAXСканер QR в мобильном приложении MAXПри pendingPassword — поле «Пароль 2FA» (sendAuthorizationPassword). Вход по коду не поддерживается.

Telegram: вход по коду

  1. На экране авторизации нажмите «Войти по коду (startAuthorization)».
  2. Введите номер телефона (например, +79990000000) и нажмите «Получить код» (startAuthorization).
  3. Введите код из Telegram и, если он задан, облачный пароль (sendAuthorizationCode). Telegram ограничивает вход по коду, поэтому надёжнее QR.
Статус blocked отображается как «Аккаунт … заблокирован». Если QR не принимается, перезагрузите инстанс в консоли и попробуйте снова.

6Чаты: общий список, фильтр, отправка и приём

Общий список и фильтр

  • «Все чаты» показывает чаты всех инстансов в одном списке, у каждого чата иконка мессенджера. Ответ уходит через тот инстанс, которому принадлежит чат.
  • Над списком переключатель: «Все инстансы» или конкретный инстанс. С ним в списке остаются только чаты этого инстанса, а в шапке появляется его мессенджер (например, «GREEN-API · WhatsApp»). Кнопка «Открыть» на карточке сразу открывает чаты одного инстанса.
  • Поиск и вкладки «Все чаты / Непрочитанные / Группы» работают поверх выбранного фильтра.

Новый чат

  1. Нажмите «Новый чат». В режиме «Все инстансы» в модалке есть поле «Инстанс»: через какой инстанс создать чат. Если выбран конкретный инстанс, используется он.
  2. Введите номер телефона (например, 79990000000) или готовый chatId и нажмите «Создать чат». Формат зависит от мессенджера:
    • WhatsApp (src/api/whatsapp.ts): номер превращается в {цифры}@c.us, принимаются также …@c.us, …@g.us (группа) и …@lid. Перед созданием вызывается checkWhatsapp. Если номера нет в WhatsApp, будет ошибка. Если API вернёт lid, он сохранится как алиас, и ответы попадут в тот же диалог.
    • Telegram (src/api/telegram.ts): только цифры — ID личного чата (10000000), -100… — группа, номер с + или скобками — чат по номеру. Ответ сопоставляется по senderPhoneNumber.
    • MAX (src/api/chatId.ts): 5–9 цифр — числовой ID чата, 10–15 цифр — номер ({цифры}@c.us), строка с @ или начинающаяся с - используется как есть.

Отправка и приём

  1. Enter отправляет сообщение, Shift+Enter переносит строку. Используется POST sendMessage. Если отправка не удалась, сообщение помечается «Не отправлено», рядом кнопка «Повторить».
  2. Приём (src/hooks/useNotificationPolling.ts): для каждого авторизованного инстанса работает свой цикл receiveNotification (long polling 5 с) и deleteNotification. Текст из textMessage и extendedTextMessage попадает в чат с тем же chatId (79990000000@c.us и 79990000000 считаются одним чатом).
  3. Исходящие с телефона (outgoingMessageReceived) и через API (outgoingAPIMessageReceived) показываются как исходящие. Дубли по idMessage отбрасываются. Каждое уведомление подтверждается, поэтому очередь не застревает.

8Установка как приложение (PWA)

GREEN-API Chat ставится как отдельное приложение: своя иконка, своё окно, без адресной строки. Установка работает и с GitHub Pages, и с Docker (нужен HTTPS или localhost).

Компьютер (Chrome, Edge)

  1. Откройте приложение. Внизу появится «Установить GREEN-API Chat как приложение?». Нажмите «Установить» или значок установки справа в адресной строке.
  2. Приложение откроется в отдельном окне и появится в «Пуске», Launchpad или списке приложений.

Android (Chrome)

  1. Нажмите «Установить» во всплывающем окне или выберите в меню ⋮ «Установить приложение» («Добавить на главный экран»).

iPhone и iPad (Safari)

  1. Нажмите «Поделиться», затем «На экран „Домой“» и «Добавить». Всплывающего предложения на iOS нет, так устроен Safari.
  2. Запускайте приложение с иконки: оно откроется без панелей браузера.

Офлайн и обновления

  • Service Worker кеширует только оболочку (HTML, JS, CSS, иконки, манифест) и шрифты. Запросы к GREEN-API никогда не кешируются, поэтому токены не попадают в кеш браузера.
  • Без сети приложение всё равно открывается и показывает сохранённые чаты, сверху плашка «Нет сети». Отправка и приём продолжатся, когда сеть вернётся.
  • Когда выходит новая версия, внизу появляется «Доступна новая версия» с кнопкой «Обновить». По кнопке страница один раз перезагрузится с новой версией.

9Запуск локально и в Docker

Требования

  • Node.js 22 LTS (минимум 20.19). CI и Dockerfile используют Node 20, Vite 8 требует ^20.19 или >=22.12, а Vitest 5 и Cypress 16 заявляют Node 22+.
  • npm и git. Для Docker нужен Docker с Compose.

Локально

git clone https://github.com/AiStockSearch/green-api-max-chat.git
cd green-api-max-chat
npm ci
npm run dev        # http://127.0.0.1:43123

В режиме npm run dev запросы идут через same-origin прокси /green-api-proxy/{host}/… (middleware в vite.config.ts). Пропускаются только хосты GREEN-API (*.api.green-api.com, *.api.greenapi.com), остальным отвечает 403 (src/api/devProxy.ts). Так браузер не блокирует запросы по CORS.

Docker

docker compose up --build
# или
docker build -t green-api-max-chat:local .
docker run --rm -p 8080:8080 green-api-max-chat:local

Приложение откроется на http://localhost:8080, проверка здоровья: curl http://localhost:8080/health → ok. Образ собирается в несколько этапов: на node:20-alpine собирается dist/ с VITE_GREEN_API_SAME_ORIGIN_PROXY=true, затем nginx:alpine отдаёт статику с SPA fallback и проксирует /green-api-proxy/* только на хосты GREEN-API, чтобы не получился open proxy. Для sw.js, манифеста и index.html nginx отключает кеш (no-cache), для /assets ставит immutable (docker/nginx.conf).

Токены в образ не попадают: в нём только статический dist/, ключи вводятся в браузере.
Статическая сборка без прокси (например, GitHub Pages) ходит в API напрямую, и браузер может блокировать запросы по CORS. Для работы с реальными инстансами используйте Docker, dev-сервер или свой backend-прокси.

Демо-режим без инстанса

Добавьте к адресу ?demo=…: интерфейс заполнится демо-данными, запросов к API не будет. Онлайн: ?demo=dashboard, ?demo=active.

  2. cypress-demo: spec 03 на демо-маршрутах, секреты не нужны.
  3. cypress-live: работает, только если заданы секреты GREEN_API_ID_INSTANCE, GREEN_API_TOKEN, GREEN_API_URL (по желанию GREEN_API_CHAT_ID, GREEN_API_MESSENGER). Без них шаг пропускается, и сообщения не отправляются.

.github/workflows/deploy.yml — Docker-образ в GHCR

Срабатывает на push в main, на теги v*.*.* и вручную. Собирает образ и публикует его как ghcr.io/aistocksearch/green-api-max-chat с тегами ветки, semver и sha: docker pull ghcr.io/aistocksearch/green-api-max-chat:main.

.github/workflows/deploy-pages.yml — GitHub Pages

  1. build: GITHUB_PAGES=true npm run build (base /green-api-max-chat/). В артефакт добавляются guide.html, screenshots/*.png и 404.html (SPA fallback).
  2. deploy: публикует демо-приложение и это руководство. Прокси на Pages нет, поэтому сайт предназначен для демо, документации и установки PWA.

13FAQ

«Неверный idInstance или apiTokenInstance», хотя ключи верные

Проверьте, нет ли лишних пробелов и совпадает ли API URL с карточкой инстанса (например, https://1101.api.green-api.com). Если токен перевыпускали, нужен новый.

«Ошибка сети / CORS: … Failed to fetch»

Запускайте через npm run dev или Docker: там есть прокси. Хостинг без прокси упирается в CORS. Хост apiUrl должен входить в allowlist (*.api.green-api.com, *.api.greenapi.com).

Сообщения уходят, а ответы не приходят

Очистите webhookUrl и включите уведомления о входящих в настройках инстанса. Закройте другие вкладки с тем же инстансом: опросы одной очереди конфликтуют. Отображается только текст.

Ответ пришёл в другой или новый чат

Входящее попадает в чат с тем же chatId. В MAX собеседник может прийти с числовым ID, в WhatsApp с …@lid. Приложение связывает lid с номером через checkWhatsapp при создании чата. Если чат создан раньше, создайте его заново по номеру.

Чем «Выйти из инстанса» отличается от «Убрать из приложения»?

«Выйти» вызывает Logout: аккаунт отвязывается, профиль остаётся. «Убрать» удаляет профиль только из браузера, к API не обращается. Подробнее в шаге 7.

Экран QR не исчезает

Сканируйте актуальный код (он обновляется каждые ~5 с) в мобильном приложении нужного мессенджера. Если просят пароль 2FA, введите его. Для Telegram можно войти по коду. При blocked проверьте аккаунт и перезагрузите инстанс в консоли.

Кнопки «Установить» нет

Chrome и Edge показывают её только по HTTPS или на localhost, если приложение ещё не установлено. В Safari на iOS установка идёт через «Поделиться → На экран „Домой“». Если приложение уже установлено, откройте его из списка приложений.

После деплоя видна старая версия

Дождитесь плашки «Доступна новая версия» и нажмите «Обновить» или просто перезапустите приложение. sw.js отдаётся без кеша, поэтому обновление находится при следующем открытии.

Live Cypress пропущен в CI

Не заданы секреты GREEN_API_ID_INSTANCE, GREEN_API_TOKEN, GREEN_API_URL. Это нормально: демо-spec и остальные проверки всё равно выполняются.

npm ci ругается на engines или не стартует Cypress

Обновите Node до 22 LTS.

Порт 43123 / 43128 / 8080 занят

Dev: npm run dev -- --port 5173. Docker: поменяйте маппинг, например -p 8081:8080.
